# 写作指南

从新建一篇文章到上线的完整流程。

---

## 1. 文章放在哪里

站点有两个栏目，各自是 `content/` 下的一个目录：

| 目录 | 导航 | 放什么 | 首页是否显示 |
| --- | --- | --- | --- |
| `content/research/` | research | 研究、可解释性、预测、做研究的方法与工具 | ✅ 显示 |
| `content/making/` | making | AI 编程、产品、设计、把想法做出来 | ❌ 不显示，只在 `/making/` 下 |

**首页只列 research。** 这是 `hugo.yaml` 里 `mainSections: ["research"]` 决定的。making 的文章仍然出现在 archives、search、标签页和 RSS 里，只是不占首页。

判断标准：写的是「研究什么」放 research，写的是「做了什么」放 making。

---

## 2. 新建一篇文章

每篇文章是一个**目录**（Hugo 叫 page bundle），正文固定叫 `index.md`，图片放同一个目录里：

```
content/research/my-new-post/
├── index.md          ← 正文
├── img-1.png         ← 图片，和正文放一起
└── img-2.png
```

**目录名就是网址**，所以用小写英文 + 连字符：`my-new-post` → `https://kxqdesign.com/research/my-new-post/`

用命令生成骨架（`<slug>` 换成你的目录名）：

```bash
hugo new content research/my-new-post/index.md
```

放到 making 就把 `research` 换成 `making`。

## 3. Front matter 怎么写

文件开头两条 `---` 之间的部分：

```yaml
---
title: 'XAI可解释人工智能学习资源'
date: 2026-07-23T21:27:00+08:00
summary: '搜索“XAI 入门”，排在最前面的往往还是 SHAP 和 LIME。'
tags: ['XAI', '可解释性', '学习资源']
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 显示在页面顶部、列表和浏览器标签 |
| `date` | ✅ | 决定排序。格式 `2026-07-23T21:27:00+08:00`，`+08:00` 是北京时间 |
| `summary` | 建议 | 列表页显示的摘要。不写的话 Hugo 自动截取开头，通常不好看 |
| `tags` | 建议 | 会生成 `/tags/xxx/` 聚合页 |
| `draft` | 可选 | `true` = 草稿，不会发布。写完删掉这行或改 `false` |
| `aliases` | 可选 | 旧网址，见下方 |

**改了网址要加 `aliases`。** 如果一篇已经发布的文章换了目录名或换了栏目，加上旧路径，Hugo 会生成跳转页，旧链接和搜索引擎收录不会失效：

```yaml
aliases:
  - /posts/forecasting/
```

**封面图。** 现在两篇转载文章都不显示封面。如果想要封面，在 front matter 加：

```yaml
cover:
  image: 'cover.jpg'
  alt: '图片说明'
  relative: true
```

小知识：即使不写 `cover`，只要目录里有个文件名带 `cover` 的图片，分享到微信/Twitter 时的预览图仍然会用它。所以「不显示封面」和「分享有预览图」可以同时成立。

## 4. 图片

放在文章目录里，用相对路径引用：

```markdown
![图片说明](img-1.png)
```

需要控制大小或居中时用 figure：

```markdown
{{< figure src="img-1.png" alt="图片说明" caption="图注" width="180" align="center" >}}
```

不要写 `/posts/xxx/img.png` 这种绝对路径——文章一旦换目录就全断了。

## 5. 中文 Markdown 的两个坑

这两个都**不会报错**，只会默默渲染错，写的时候留意：

### 坑一：粗体贴着中文标点会失效

```markdown
❌ 他在**《论语》**中说      → 渲染成字面的星号
✅ 他在 **《论语》** 中说     → 星号外侧加空格
✅ 他在<strong>《论语》</strong>中说   → 或直接用 HTML
```

原因：CommonMark 规定 `**` 紧贴标点时不能开启强调。`《》：，。` 都算标点，所以中文里特别容易踩。

### 坑二：`---` 上面必须空一行

```markdown
❌ 正文最后一句。
   ---

✅ 正文最后一句。

   ---
```

紧贴文字的 `---` 会把上一行变成标题，而不是分隔线。

## 6. 本地预览

### 首次安装 Hugo

```bash
winget install Hugo.Hugo.Extended
```

必须是 **Extended** 版本，主题要用它编译 SCSS。装完开一个新终端，确认：

```bash
hugo version
```

### 每次预览

```bash
cd C:\Users\s398876\Documents\kxqdesign\kxqdesign.github.io
```

```bash
hugo server --renderToMemory
```

浏览器打开 <http://localhost:1313>，改完文件保存会自动刷新。`Ctrl+C` 停止。

> ⚠️ **`--renderToMemory` 不能省。** 少了它，`hugo server` 会往 `public/` 里写文件——那个目录是被 git 跟踪的，会凭空多出十几个改动混进你的提交。

想连草稿一起看：

```bash
hugo server -D --renderToMemory
```

### 发布前完整构建一次（可选）

```bash
hugo --gc --minify --destination C:\Users\s398876\AppData\Local\Temp\hugo-check
```

这条命令和 GitHub 上的自动构建一模一样，输出没有 `ERROR` 就说明能正常发布。`--destination` 指向仓库外面，同样是为了不弄脏 `public/`。

## 7. 提交与发布

```bash
git status
```

先看一眼改动。**应该只有 `content/` 下的文件**。如果冒出一堆 `public/` 的改动，说明预览时忘了 `--renderToMemory`，清掉它们：

```bash
git checkout -- public && git clean -fd public
```

确认干净后：

```bash
git add content/
```

```bash
git commit -m "Add post: XAI 学习资源"
```

```bash
git push
```

**push 之后自动发布。** GitHub Actions 会构建并部署，通常 1–2 分钟。可以在这里看进度：

<https://github.com/kxqdesign/kxqdesign.github.io/actions>

绿色勾 = 已上线，去 <https://kxqdesign.com> 刷新查看（可能要 `Ctrl+F5` 强制刷新绕过缓存）。

## 8. 出问题时

| 现象 | 原因 / 处理 |
| --- | --- |
| 本地能看到，线上没有 | 文章还是 `draft: true`；或 Actions 还在跑/失败了 |
| 线上还是旧内容 | 浏览器缓存，`Ctrl+F5` 强制刷新 |
| 文章没出现在首页 | 放进了 `content/making/`，首页只显示 research，属正常 |
| 图片裂了 | 图片没和 `index.md` 放同一目录，或用了绝对路径 |
| 星号变成了字面文字 | 坑一，粗体贴着中文标点 |
| `git status` 一堆 public/ 改动 | 预览时忘了 `--renderToMemory`，按第 7 节清理 |
| Actions 变红 | 点进去看失败的那一步。若提示 action 版本过期，把 `.github/workflows/hugo.yaml` 里的版本号升到最新 |

## 附：以后要新增第三个栏目怎么办

不只是建个目录就行，有两处必须同时改，否则文章会静默从首页消失：

1. 建 `content/<新栏目>/_index.md`，写上 `title` 和 `description`
2. 在 `hugo.yaml` 的 `menu.main` 里加一项
3. 如果希望它也出现在首页，把栏目名加进 `params.mainSections`

`mainSections` 没配的时候 Hugo 会自动挑「页面最多的那个栏目」——栏目数量一变，首页显示什么就会跟着变，而且不报错。所以新增栏目后一定要显式确认这一项。
